Definição técnica

📘 Definição
Um endereço IP (Internet Protocol) é um número que identifica um dispositivo dentro de uma rede — é o "endereço" que outros equipamentos usam pra saber pra onde mandar dados. Todo dispositivo conectado (computador, celular, roteador, câmera, NVR) tem um IP enquanto está naquela rede.

No formato mais comum, chamado IPv4, esse número aparece como 4 partes separadas por ponto — por exemplo 192.168.1.19. É esse formato que você vai ver o tempo todo nas telas de configuração de câmera, roteador e NVR.

Uma analogia pra fixar

🧩 Analogia
Pensa num endereço de casa: rua, número, bairro. O carteiro usa isso pra saber exatamente onde entregar uma carta, mesmo sem conhecer você pessoalmente. O IP faz a mesma coisa dentro da rede: o roteador não "conhece" o dispositivo, só sabe pra qual número mandar os dados.
🎥 No nosso projeto
O NVR (gravador) das câmeras de Piazza Fontana tem o endereço 192.168.1.19 dentro da rede daquele prédio. Sempre que algum equipamento na mesma rede quer "conversar" com o NVR — pra ver a imagem, configurar algo — é esse número que ele usa.

Anatomia de um IP (versão que usamos: IPv4)

🔢 Como o número é montado
Um IP no formato IPv4 tem 4 números separados por ponto, cada um de 0 a 255 — por exemplo 192.168.1.19. Cada um desses 4 números é chamado de octeto (porque, por trás, é um byte de 8 bits — e 8 bits vão exatamente de 0 a 255). Os 4 octetos juntos formam um número de 32 bits — é esse o tamanho total de um endereço IPv4.

IPv6 — por que existe e por que CFTV ainda não usa

ℹ️ O problema que o IPv6 resolve
Um IPv4 de 32 bits permite cerca de 4,3 bilhões de endereços diferentes — parece muito, mas o mundo já tem mais dispositivos conectados do que isso. Por isso foi criado o IPv6: endereços de 128 bits (tipo 2001:db8::1), um espaço tão maior que não tem risco de esgotar de novo.
🎥 No nosso projeto
Mesmo assim, o universo de câmeras/CFTV — incluindo o NVR de Piazza Fontana — ainda opera quase todo em IPv4. Na prática, a grande maioria dos equipamentos desse mercado (interface de configuração, apps de cliente, integração com nuvem de câmera) só oferece IPv4 mesmo hoje. É nele que este curso foca do início ao fim.

IP fixo x IP dinâmico (DHCP)

🔁 Como um dispositivo recebe o seu IP
A maioria dos dispositivos (celular, notebook) recebe o IP automaticamente do roteador, via um protocolo chamado DHCP — toda vez que reconecta, pode receber um número diferente. Já um IP fixo (estático) é configurado manualmente no próprio dispositivo e nunca muda sozinho.
⚠️ Por que isso importa pro NVR e pras câmeras
Se o NVR ou uma câmera usar DHCP, o IP pode mudar sozinho depois de uma queda de energia ou reinício do roteador — e nesse momento o NVR "perde" a câmera (ela some da lista, porque o NVR ainda está procurando o IP antigo). Por isso o padrão do mercado de CFTV é IP fixo pra NVR e câmeras: ou configurado direto no equipamento, ou por reserva de DHCP no roteador (o roteador sempre entrega o mesmo número pra aquele dispositivo específico, mas ainda por DHCP).

Isso na prática

Veja o que acontece, passo a passo, quando alguém de fora tenta acessar o NVR das câmeras direto pelo IP dele:

  1. Celular fora de casa tenta abrir 192.168.1.19 direto no navegador/app.
  2. O pedido viaja pela internet até chegar no roteador de Piazza Fontana — no IP público dele, 189.45.12.30.
  3. O roteador procura o dispositivo 192.168.1.19 dentro da própria rede local.
  4. Esse endereço só existe dentro daquela rede — nenhum roteador do mundo sabe rotear pra ele vindo de fora.
  5. Resultado: "não foi possível conectar". O IP está certo, mas é privado — inalcançável de fora sem mais alguma coisa.

Por que isso importa pro nosso projeto

📌 Resumo
  • Todo dispositivo numa rede tem um IP.
  • No formato mais comum (IPv4), são 4 octetos de 0 a 255, tipo 192.168.1.19 — 32 bits no total.
  • IPv6 existe pra resolver a escassez de endereços, mas CFTV ainda opera quase todo em IPv4.
  • NVR e câmeras devem ter IP fixo (ou reserva de DHCP) — nunca automático puro — pra não sumir da rede sozinhos.
  • Só ter o IP de um NVR/câmera não garante acesso de fora — isso depende do TIPO de IP.

No próximo tópico vem a peça que realmente resolve o mistério de "por que eu não conseguia acessar a câmera de fora": a diferença entre IP privado e IP público.

Checkpoint final

Múltipla escolha
Um IPv4 tem quantos bits no total (contando os 4 octetos juntos)?
Confiança:
4 octetos de 8 bits cada = 32 bits no total. 128 bits é o tamanho do IPv6, não do IPv4.
